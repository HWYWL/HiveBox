# 🗣 HiveBox 固件更新 `v0.13.0-20261126`

这一版只加了一件事，但它可能是最实用的那件事：**板子会回话了** 💬

---

## ✨ 串口回声：发什么，回什么

插上数据线，开个串口工具（115200），敲一行：

```
> hello hivebox
收到数据 ===> hello hivebox
```

中文、数字、长字符串都行：

```
> 你好，板子
收到数据 ===> 你好，板子
```

超过 128 字节会分几次回 —— 读多少回多少，不攒也不丢。

## 🧭 为什么值得做

前阵子这块板子黑过一次屏。当时最难受的不是黑，是**不知道它到底活着没有**：

- 屏幕不亮 → 可能是屏坏了，也可能是应用根本没跑
- 网页打不开 → 可能是 Wi-Fi 没连上，也可能是服务没起
- 串口一片安静 → 可是它本来就不怎么打印

一行回声把这件事一刀切开：**能回，固件就在跑；不回，问题在它之前。** 比拆机、比万用表都快。

## 🔌 用的是哪条串口

芯片自带的 **USB Serial/JTAG**，就是插上数据线出现的那个 `COM3`，不用另找引脚 —— 这块板子的控制台本来就挂在这条线上：

```
CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y
```

以后想换到引出的硬件 UART，只需要把 `board_serial.c` 里三个 `usb_serial_jtag_*` 换成 `uart_*`，逻辑一行都不用动。

## 🛠 实现上的三个决定

**1. 排在显示初始化之前**

`board_hal_init()` 里，回声任务是第二个初始化的东西（紧跟日志环）。屏幕起不来的时候，恰恰最需要这条串口 —— 不能让它跟着屏幕一起等。

**2. 用驱动自己的写入，不走 `printf`**

日志和回声是同一根线上的两个出口。回声走 `usb_serial_jtag_write_bytes`，省得和 IDF 控制台抢同一个缓冲区。

**3. 写不进去就丢**

主机没在读（串口工具没开）时，写会超时。这时**丢掉这一次**，绝不把任务卡在那里等 —— 回声是给人看的，不该有副作用。

## 🧩 依赖上的一个小坑

ESP-IDF 6 把 USB Serial/JTAG 从 `driver` 里拆成了独立组件 `esp_driver_usb_serial_jtag`，不显式写进 `PRIV_REQUIRES` 就会：

```
fatal error: driver/usb_serial_jtag.h: No such file or directory
```

已经在 `CMakeLists.txt` 里补上了，注释写在旁边。

## 📌 顺带回顾上一版
