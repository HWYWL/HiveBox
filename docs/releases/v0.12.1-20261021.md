# 🔧 HiveBox 固件 `v0.12.1-20261021`

一个 bug 的修复版：**更新页说「没有连上服务器」**，现在好了 📡

---

## 🐛 先说现象

`v0.12.0` 里点「更新」→ 检查，屏幕上只有一句：

> 没有连上服务器。

但同一块板子上，DeepSeek 明明能读到余额 —— 网络是通的，`gitee.com` 从电脑上也能打开。

## 🔍 真凶：被自己挤死的内部 RAM

拆开看，是这么一条链：

1. 更新页要下载清单，得先建一个 **8 KB 栈**的后台任务
2. 这块板子的内部 RAM 只剩 **11 KB**，而且**最大的连续块只有 7.5 KB**
3. `xTaskCreate` 要一块**连续**的 8 KB → 差 500 字节，失败
4. 失败被上层翻译成了「连不上服务器」🙃

问题不在网络，在于**内部 RAM 一块都拿不出来**。

## 📦 谁吃掉了那 22 KB

是**日志环**：网页上「日志」那一页读的最近一百多行 `ESP_LOG`，24 行 × 900 字节，放在 `.bss` 里 —— 也就是**开机就常驻内部 RAM**。

日志是冷数据，没人要求它住在最贵的那块内存里。

**改动**：日志环改成运行时从 **PSRAM** 申请（这块板子有 3.4 MB），申请不到就只是「日志页空着」，不影响开机。

## 📊 前后的数

| | 修前 | 修后 |
|---|---|---|
| 内部 RAM 空闲 | 11 KB | **34 KB** |
| 最大连续块 | 7.5 KB | **23 KB** |
| 更新页 | ✗ 没有连上服务器 | ✓ 已是最新 |
| DeepSeek 读一次 | ✗ 时好时坏 | ✓ 稳定 |

## 🐋 顺手把 DeepSeek 的 96 KB 也挪了

那 96 KB 的响应缓冲原来是**开机就要**，而且「要不到 PSRAM 就退回 `malloc`」—— 一旦退回，九十六 KB 直接砸进内部 RAM，整块板子当场喘不过气（这一版之前它确实这么干过）。

现在：**第一次真正去读的时候才要，而且只要 PSRAM**。要不到就明说这一页读不了，绝不连累别人。

## ✅ 现在的样子

- 更新页：`固件 当前 v0.12.1` → **已是最新**；`字库 当前 v3` → **已是最新**
- DeepSeek 页：余额 109.02、今日 0.71 / 94 次 / 7.44M、24 小时柱状图，全部正常

## 💡 留个提醒

这块板子的内部 RAM 一直很紧（三十来 KB 的量级），**任何「开机就 malloc 几十 KB 到内部」的代码都会引发别处的故障** —— 而且是那种「A 功能坏了，原因在 B 的初始化里」的故障。以后再有新的常驻缓冲，先想想能不能放 PSRAM。
