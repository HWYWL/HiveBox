# 🖥 HiveBox 固件更新 `v0.14.0-20261127`

这一版把面板上那个终端 **搬到了 23 端口**：坐在电脑前 `telnet` 进来，敲的就是屏幕上那个 shell 里的命令 🎛

---

## ✨ 23 端口有个终端

板子和你在同一个局域网里，直接连：

```
$ telnet hivebox.local
pomelo:/internal$ ls
Applications   bin   fonts   ...
pomelo:/internal$ free
```

没有第二套命令。`ls`、`cd`、`cat`、`rm`、`pwd`、`echo`、`free`、`wifi`、`clear`、`help`
在这儿和在面板上一字不差 —— 连「命令写错了」那句提示都是同一句。它们在面板上的行为为什么
是对的，在这里就为什么是对的，因为**它们本来就是同一个东西**。

## 🧵 一行命令是怎么走过来的

输入的不是「命令行」，是按键：

```
这一行 "ls -l\r\n"
   ↓  拆成 KeyAction::Char / Space / Enter
TerminalModel::handle_key_action()
   ↓  和屏幕上那块虚拟键盘走的是同一条路
commands/ 里注册表里那个 ls
   ↓  只把「还没发过」的历史行写回 socket
你的终端
```

所以新加一条命令，只改 `commands/` 一处，面板和 telnet 两边自动都有 —— 不需要记得去同步
第二份实现，因为不存在第二份。

## 👥 一次只服务一个人，而且说清楚

**每条连接有自己的一份 `TerminalModel`**，也就是自己的 cwd 和历史。两个人连进来，不会互相
把对方 `cd` 走。

但**同一时刻只跑一条会话**，第二条连接会收到一句话然后被挂断：

```
这个终端一次只服务一台设备，已经有人连着了 —— 等他断开再来。
```

这不是偷懒，是算术：每条会话一条线程、一份 10 KB 栈，这块板子的内部 RAM 本就不宽裕
（日志环那一版之后才从 11 KB 回到 34 KB）。实测第二个会话的线程根本开不出来，客户端连
招呼都收不到。与其让人对着黑屏猜，不如明说「满了」。

## 🔌 协议只做必须做的那一点

Telnet 不是「裸 TCP 加回车」，光连上来就会先来一串 `IAC` 协商字节。这一版处理了三件事：

- **吃掉的**：进来的 `IAC cmd opt` 三个字节不当正文 —— 不然第一个提示符前面会冒出一串乱码；
- **声明的**：主动 `WILL ECHO` 与 `WILL SUPPRESS-GO-AHEAD`，由服务端负责回显，客户端就不会
  再自己回显一遍（否则打一个字出现两个，退格擦掉的也只是半个）；
- **不做的**：窗口大小、行模式、认证……一概不实现，用不上。

## ⌨️ 几个真的动手才发现的坑

**1. 回车来了两次**

Windows 的客户端发 `\r\n`。逐字节处理就是一个回车变两次执行，于是记住了「上一字节是不是
`\r`」，`\n` 紧跟着就跳过。

**2. 同一行命令出现两次**

客户端已经把这一行回显在屏幕上了，服务端再把模型的提示符行发一遍就是两行。所以按下回车时
先发 `\r\x1b[2K` 把自己回显的那一行擦掉，再让模型自己说。

**3. 一个汉字是三个字节**

`你` 的 UTF-8 是 `E4 BD A0`，逐个字节 `str::from_utf8` 全失败。所以先攒进 `pending`，凑齐
一个完整字符再回显、再进缓冲区；攒满 4 字节还不是合法 UTF-8 就丢掉，免得一个坏字节卡死后面
所有输入。

**4. `clear` 之后屏幕还在**

`flush` 只发「新增的行」，而 `clear` 是把历史整个清空 —— 行数变少。于是拿上次发过的行数一
比：变少了就当屏幕被清过，发一个 `\x1b[2J\x1b[H`，从头再发一遍。

## 🚪 明文，没有口令

和网页那边一个立场：绑 `0.0.0.0`，局域网里用，**没有密码**。谁能连上 23 端口，谁就能跑
`rm`。这是选择，不是疏漏 —— 用之前应该知道自己在什么网络上。

## ⚠️ 应用分区只剩 2%

这一版之后 `firmware.bin` 是 `0x5df7b0` 字节，最小应用分区 `0x600000`，只剩 **2%**。还能
编、还能刷，但下一版加东西之前得先腾地方（或者调分区表）。
